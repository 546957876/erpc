# Embedded Admin Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dark, compact Admin Web that manages explicit EVM upstreams and ships inside the eRPC binary at GET /admin/.

**Architecture:** React Router owns guarded page navigation, Redux Toolkit plus redux-persist owns session/global UI state in sessionStorage, and TanStack Query owns all Admin API server state and mutation invalidation. Vite builds a standalone web/dist tree that a small Go web package embeds; GET/HEAD under /admin/ serves the SPA while POST /admin remains the existing JSON-RPC endpoint.

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, Ant Design 6, Tailwind CSS 4, React Router 7, Redux Toolkit 2, React Redux 9, redux-persist 6, TanStack Query 5, MSW 2, Vitest 4, Go embed.FS.

---

## Prerequisite and state ownership

Complete docs/superpowers/plans/2026-08-26-admin-upstream-controller.md first so
the four upstream methods and their wire errors are stable.

Do not duplicate ownership:

- React Router owns the current page and deep links.
- Redux owns the admin token, selected project, and global UI preferences.
- redux-persist persists only the session slice through sessionStorage.
- TanStack Query owns taxonomy, config, projects, networks, upstream lists,
  loading/error state, caching, polling, and invalidation.
- Ant Design Form owns open drawer drafts; search and row selection stay local.

This is an expandable application shell, not a one-page hand-written state
machine. No page component calls fetch directly.

- [ ] **Step 5: Implement AdminRpcClient**

Constructor inputs are endpoint, getToken, and onUnauthorized. call builds a
JSON-RPC request with an incrementing numeric ID, sends content-type and
x-erpc-secret-token, validates matching response ID, and throws AdminRpcError.
Use import.meta.env.DEV ? "/admin-api" : "/admin" as the endpoint.

Unauthorized is response.status === 401 or error.code === -32016. It calls
onUnauthorized once and throws kind "unauthorized". Error kind otherwise comes
from error.data.kind without enumerating unknown future kinds.

- [ ] **Step 6: Implement query keys and hooks**

Use factories:

~~~ts
export const adminQueryKeys = {
  all: ["admin"] as const,
  taxonomy: () => ["admin", "taxonomy"] as const,
  config: () => ["admin", "config"] as const,
  project: (projectId: string) => ["admin", "project", projectId] as const,
  upstreams: (projectId: string) => ["admin", "upstreams", projectId] as const,

~~~

useUpstreamsQuery polls every 10 seconds while mounted and does not poll in a
background tab. Mutations call the matching Admin method, then invalidate
upstreams(projectId), project(projectId), and taxonomy. Conflict on update or
delete first awaits refetchQueries(upstreams(projectId)), then rethrows.
TanStack Query retries queries twice for transient errors and never retries
unauthorized or mutations.

adminQueries.ts exports useTaxonomyQuery, useConfigQuery, and
useProjectQuery(projectId) using the same AdminRpcClient and query-key factory.
The shell and read-only pages consume these hooks; they never call the client
or fetch directly.
